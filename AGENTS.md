# FiHaven — notes for agents

## CI must be green on both remotes before a PR is called done

- Every push runs the `Codecov` workflow (`npx vitest run --coverage`) on
  GitHub. Check it with `gh run list --branch <branch>` — do not report a
  branch as pushed-and-clean while it is red.
- The Forgejo mirror (`forgejo` → git.greighstudios.com:greighstudios/FiHaven)
  also runs `.github/workflows` via its own Actions. Check
  `https://git.greighstudios.com/api/v1/repos/greighstudios/FiHaven/actions/tasks`
  for run status on the branch.
- As of 2026-10-04 the Forgejo runner fails every run in ~2s (including runs
  on its own `main`) — runner-level infra failure, not the suite. Verify
  runner health before blaming code.

## Test hygiene

- Anything that loads `server/db.js` must be hermetic: set
  `FIHAVEN_TEST_DB_PATH` to a scratch file per run, or stub `./db`. The dev
  database at `data/cleartab.db` is real data on a newer schema — tests that
  open it for real will crash at module load.
- `bun test scripts/` covers `scripts/*.test.js`; vitest does not include
  `scripts/`.

## Repo layout

- `npm run ci` — the artifact gates (csp, sitemap, markdown, logos, sh-parse,
  store-notes) plus vitest.
- The Xcode project is generated by XcodeGen and git-ignored; `run-ios.sh` /
  `run-macos.sh` regenerate it when `project.yml` or any `Sources/*.swift`
  is newer than `project.pbxproj`.
- Maintainer docs live in `docs/maintainer/` (see its README).
- Local `main` and the remotes' `main` currently share no commit history —
  PRs cannot span them; port the diff instead (see the Dexio session page
  `projects/fihaven/2026-10-04-stores-live-badges-and-ledger`).
